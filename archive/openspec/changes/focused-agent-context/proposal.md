# Proposal

## Why

The user requested project-specific token/workflow optimization. Automatically
loaded instructions mix closed authorizations with current rules; mandatory broad
reads and repeated receipts cause avoidable context growth and stale decisions.

## What Changes

- Consolidate current authority, task-based context routing and optional prepared
  Luna execution, preserving runtime gates and evidence requirements.
- Keep STATUS current-only; preserve original documents as historical snapshots.
- Add a read-only bounded project-context command and compact worker template.
- Align the development-workflow specification and OpenSpec context with the
  user's superseding permissions. No training/model/game behavior changes.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `development-workflow`: focused startup, bounded read-only handoff and current
  single-primary/optional-script-worker ownership.

## Impact

Project instructions/docs, one PowerShell read-only helper and OpenSpec workflow
artifacts. No new dependency, MCP server, global configuration or runtime action.
Acceptance: original snapshots match; links/config/spec validation passes; helper
JSON/text, alternate working directory, size refusal and Git-output cap are checked;
all current permissions and pending native acceptance remain explicit.
