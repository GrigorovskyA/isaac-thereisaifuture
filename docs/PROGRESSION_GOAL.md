# Final goal and operating interface

The user specified Dead God on **save file 2**, earned through gameplay, as the
final target on 2026-10-17. Full runs are an intermediate result. The target
interface is one script opening a terminal with logs, starting Isaac and
connecting the structured bridge. Normal operation must not depend on monitor
capture or screen coordinates. The user authorized local menu-only keyboard input;
gameplay state and actions use the Lua/API bridge. A script launcher is distinct from a
development-session runner and does not require an orchestrator.

## Present increment

Start-IsaacAgent.cmd now attempts bounded local file2/Continue entry without
screenshots. Fresh selected-slot metadata and [Continue,2] native log evidence
must precede a validated bridge snapshot. Focus/state failure stops input. Existing
file2 Continue is required; no new-run fallback or training starts. Native evidence
and remaining limits are recorded in reports/2026-10-20-local-menu-entry.md.

## Earlier observation-only increment

Start-Isaac.cmd launches bounded read-only observation. It does not yet select
file 2, attest the active slot, start/continue a run or train/control a player.
The terminal explicitly identifies manual slot selection as a limitation.
This earlier research sought a supported menu API and separate real evidence.
The [REPENTOGON SaveMenu API](https://repentogon.com/menus/SaveMenu.html) documents
GetSelectedElement/SetSelectedElement, making it a research candidate. REPENTOGON
is absent locally; element selection is not proof of loading a specific file.
Its J460 support, index mapping, confirmation/load semantics and identity readback
must be audited before adoption. The baseline launch-options documentation has no
verified file-selection flag. No extender was installed for this research.
Unknown identity must block automatic Continue rather than silently use
another file. See [launcher guide](LAUNCHER.md) and the active OpenSpec change.

The already-running ordinary game was left untouched during launcher development.
The existing permission exception covers read-only observation after backup;
this goal declaration does not authorize resets, save changes, online interaction,
Cloud changes or unbounded training.

## Completion evidence and dependencies

Version-specific research must establish completion marks, challenges, collection
and unlock prerequisites, special modes, daily/time requirements and achievement
eligibility. Maintain a persistent ledger for file 2 with current/remaining goals
and versioned evidence. Global Steam achievements alone cannot prove that this
specific file is complete. Verify the actual in-game Dead God state and durable
progress after normal exit/restart; synthetic rewards and edited/imported saves
cannot satisfy the target. Count autonomous and user-assisted completion separately.

The publisher's [Repentance+ release FAQ (2024-11-18)](https://store.steampowered.com/news/posts/?appids=250900&enddate=1744390716&feed=steam_community_announcements)
states that new Dead God files require online achievements, and mods must be
disabled for online play. Read on 2026-10-17; this is historical publisher evidence,
not verification of current J460 behavior. Whether a fully autonomous mod-based
agent can satisfy all current requirements is **unknown**. Reverify that dependency
and legitimate mod/debug achievement eligibility before designing the campaign.
Do not install an extender, manipulate achievements or enable online interaction
to resolve it without the corresponding authorization and compatibility work.

Roadmap items 19–21 cover slot/eligibility, progression tracking/goal selection and
the final campaign. Item 02 real observation acceptance remains the immediate
dependency; learning and campaign progress have not begun.
